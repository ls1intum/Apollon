# App Store release readiness

The repository contains the repeatable parts of an App Store release:

- the existing App Store bundle identifier, `de.tum.cit.ase.apollon`;
- the legacy Apollon app icon and launch-screen design;
- localized public metadata in `fastlane/metadata`;
- real iPhone and iPad Simulator screenshots generated by XCUITest;
- Fastlane lanes for TestFlight, assets-only updates, and App Store uploads; and
- a manual GitHub Actions workflow whose App Store review submission is opt-in.

## Before uploading

- Merge and deploy the documentation before running an App Store destination.
  The release workflow validates the marketing, support, and privacy URLs and
  stops before any upload if one is not a public HTTPS page.
- Install an App Store build of the old native app, add representative diagrams,
  then update it in place with the new build. Verify the legacy migration on an
  iPhone and an iPad and export a backup before testing. See
  `ios/App/App/Migration/README.md`.
- Open `fastlane/screenshots-review.html` and review both the untouched
  Simulator masters and framed candidates at full size. Confirm the upload
  style in the release workflow.
- If using the framed set, have an authorized Apple Developer Program
  representative accept Apple's product-bezel license and install the current
  official assets under the ignored `fastlane/device-frames/` directory. The
  release lanes fail closed rather than substituting unofficial frames.
- CI fetches the approved, checksum-pinned packages directly from Apple and
  publishes a screenshot review artifact before uploading. A changed package
  fails validation before its bundled terms are accepted.
- Verify the version and build number, signing certificate, provisioning profile,
  distribution agreements, tax and banking status, and DSA trader status in App
  Store Connect.
- Provide the App Review contact name, email address, and phone number in App
  Store Connect. These personal fields are intentionally not committed.

## App Privacy

The previous listing says that no data is collected. That answer needs a manual
review because the redesigned app can optionally upload diagram content when a
user creates a share link. The privacy policy says shared diagrams are stored
for up to 120 days and that the service has no account system, advertising, or
third-party analytics.

Based on that behavior, the likely App Privacy declaration is:

- **User Content → Other User Content**
- collected only when the user chooses the sharing feature
- used for **App Functionality**
- not used for tracking
- not linked to an identity

This is a release-owner decision, not a value Fastlane can safely infer or
submit. Reconfirm it against the production server and Apple’s current
questionnaire before release.

## Upload paths

Run the manual `ios-release` workflow with:

- `testflight` for internal testing;
- `app-store-assets` to update metadata and screenshots without a binary; or
- `app-store` for the complete upload.

For either App Store destination, choose `raw` or `framed` under **Screenshot
presentation**. The approved official-bezel treatment is the default; choose
`raw` only to upload the untouched Simulator captures instead. From a local
Fastlane invocation, set `APP_STORE_SCREENSHOT_STYLE=raw` to select the raw
masters.

Keep **Submit for review** disabled until the upgrade/migration test, privacy
answers, review contact, agreements, and screenshots have all been approved.
